## 5. 수집 안정성
- 재시도: 3회(5·20초 간격, 접속 10초·응답 30초). 404 등은 즉시 포기
- **403(디지털데일리)**: 원인은 웹서버(nginx)의 **실행 서버 IP 단위 차단**으로 판단(같은 서버 재시도는 계속 403, 새 서버는 성공). 같은 서버 재시도 생략 → 수집 작업의 `retry-403` 단계가 **새 서버에서 즉시 재수집**(1~2분 내 회복 확인). 첫 시도 403(`retry:403`)은 연속 실패 횟수에서 제외. 403 응답의 서버·헤더·본문 앞부분을 진단 기록
- **접속 시간 초과(전자신문, 2026-10-27 사용자 승인)**: 10/26~27 실패 11건 모두 `ConnectTimeout`(같은 서버 3회 무응답, 다른 매체는 정상, 새 서버는 대개 성공) → GitHub 실행 서버 IP 단위 무응답으로 판단. 403과 같이 같은 서버 재시도 생략 + 새 서버 즉시 재수집(`retry:conn`/`retried:conn`), 첫 시도는 연속 실패 횟수에서 제외. 전자신문 RSS(`rss.etnews.com/04045.xml`, 같은 AI·SW 보안 절, 50건)는 GitHub 서버에서 열리지만 같은 시험에서 SSL 끊김이 2번 나 보조 수집원으로 바로 쓰지는 않음
- 누락 감지: 목록의 가장 오래된 기사가 마지막 성공보다 늦으면 '놓친 기사 가능' 표시
- 매체별 실패 알림 기준: 디지털데일리·디지털투데이 2회, 나머지 3회
- 숨은 지시문 점검: 수집 원문 검사, 의심 원문은 `data/suspicious/`에 영구 보관(디지털타임스 건은 오탐 확정)

## 6. 한 줄 요약 (AI)
- **매시간 수집 끝에 Claude Haiku 5.5**(`claude-haiku-5-5`, API 버전 2026-10-21)로 새 공개 대상 기사 요약 — 사용자 결정(Sonnet 검토 후 Haiku로 확정)
- 규칙: 첫 문장 옮기기 금지, 기사 핵심(누가·무엇을·영향/규모)을 40~60자 헤드라인식. 입력에 없는 사실·기자명·매체명 금지
- 검증 통과분만 저장: 15~80자, 한 줄, 링크·기호 없음, 지시문 의심 없음, 제목 반복 아님. 탈락분은 다음 수집 때 재시도, 48시간 실패 시 포기(`none`)
- 묶음 15건·응답 상한 8,000토큰(25건일 때 응답 잘림 발생 → 수정), 잘린 응답에서도 완성 항목 복구
- 요약 전에는 칸을 비워 둠(규칙 발췌문을 요약으로 쓰지 않음 — 사용자 결정). 설명이 없는 기사는 기사 페이지 설명 태그로 재료 보완(1회 최대 5건)
- AI 요약이 없는 보안·업계 기사만 브리핑 작업이 보완(`needs_line`). 브리핑 입력에 AI 요약(`ai_line`)을 함께 제공(분류·사건 묶기 참고)
- API 키: GitHub Secrets `ANTHROPIC_API_KEY`(사용자 등록). 비용: 하루 150건 기준 **월 1달러 미만**, 사용자 API 크레딧 월 100달러. 월 20달러 초과 시 주의
- `summary_source`: ai(매시간 AI) / claude(브리핑 보완) / none(포기)
